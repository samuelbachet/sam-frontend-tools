# Front-End Developer Tools
By: Samuel Bachet

I wanted optimize how I worked with conventional HTML + CSS for static design because memorizing elements, semantics, and rules is a very tedious task.
So I decided I would lay the foundation for a starting point that uses Pico CSS while having enough project references to approach the workflow smarter, not harder.

Here you can find a handy bundle that makes learning and working with HTML + CSS styling easy. Relevant licensing and .gitignore files can be found as well.
Pico CSS is used ground up for the styling sheet : [Pico CSS](https://picocss.com)

## Includes:
1. A syntax companion to grab elements and style rules on the fly.
2. Color palette markdown file to keep track of the colors for your themes and other palettes. <- ** Essential design practice
3. HTML and CSS templates to get you started from a baseline that complies with semantics and Pico's rules
     i) You can find 'template.html' in  the 'site' folder, which contains frequently used elements as well as a template.css to see how those elements can be styled
   ii) 'index.html' uses the gobal Pico rules in styles.css, go from there.
4. Use the templates as a guideline to see where elements need to be placed, how they are styled and then use the syntax companion for anything else you may need.

Feel free to branch this with changes or more powerful additions if you feel it necessary.

## A word on learning Front-End:
I have met many other aspiring devs in the past tell me that front-end development is a PITA but it's all about how you approach it.

This is ideal for those of you looking to actually learn how to manually design static sites with (close to very conventional) HTML + CSS from the ground up, than to depend on AI to do it for you.
Obviously I used AI to generate the template to get all those various elements and styles in one place, however, the point is that you can take it from here to actually learn by seeing how elements are ordered and how they look on a webpage, seperate from your main project environment. This is my workflow, maybe it will work flow you too.

Try different elements, styles, colors and use the companions and palettes to aid your apparoach and develop a workflow where you actually have a grasp of what you are building. 
That is how you learn.

The main issue with static front-end development through AI is that it inserts an abundance of advanced CSS rules that you probably have no idea what they do, why they are there and most likely do net need them. Thus potentially going beyond the scope of your project to the point that scaling up becomes like trying to read word salad instead of being productive.

If it looks the way you want, that's all you need it do. Once you need to go interactive, that's when you can begin to consider how to approach more intentional styling through more advanced CSS rules.

Getting the essentials down is crucial if you want to be able to say that you know what the **** you are talking about and that everything you made was done with intent. I guarantee you that the scale of what you want to put in place takes 1/4 of what AI has made for you in the past. Such is true for virtually everything in this modern dev space today.
